# paged.sheet — full analysis

**v1.0 · 2026-10-04 · input for the performance, testing and Excel-parity work**

What `paged.sheet` is today, measured against the everyday fundamentals of a spreadsheet as
Excel defines them, plus the test, CI and performance state as found. The scope rule of
[ADR 504](../adr/504-publishing-first-scope.md) stays: a publishing instrument, not an Excel
replacement. What ships is listed in [`status.md`](../status.md); this record is the
analysis behind the next round of work and the corrections it made to other records.

Evidence tags, used on every claim that matters:

- **[C]**: verified by reading code or by grep on 2026-10-04 (the grep is named where
  absence is claimed).
- **[M]**: measured on 2026-10-04 by running it.
- **[S]**: reported by one of the three surveys and not re-verified. Treat it as a lead.

Paths are relative to this repository unless they name another one; `B` stands for
`packages/sheet-bundle/src`. Code lines are read at commit `f7e84e1`, whose code is identical
to `71f37d7` (the commits between them change documentation and comments only).

## 1. Method

Three read-only surveys (performance hot paths; tests and CI; feature gaps against Excel,
the feature registry, the platform gap register and the host doors), then a re-check of every
headline claim by grep against this repository, the engine (`paged-media/core`) and the
plugin contract (`paged-media/plugin-sdk`). Two survey claims were wrong and one gap had
already been closed in the engine; §8 lists them. The plan follows the shape used for
`paged.draw` and `paged.image`: gates and pins first, a count-based measurement harness,
optimisations that lower a budget in the commit that earns them, oracle-driven correctness,
the missing fundamentals, and one batched engine protocol change.

## 2. Headline

1. **Edits are lost on reload.** The workbook is written to its container part and blob
   only on import: `persistWorkbook` (`packages/sheet-bundle/src/session.ts:760-773`) has one
   caller, `loadWorkbook` with `persist = true` (`packages/sheet-bundle/src/session.ts:814`).
   A cell edit, sort, replace, paste or dataset-sourced workbook lives in memory; reopening
   the document restores the last imported bytes. [C]
2. **The TypeScript lane cannot fail.** `.github/workflows/vitest.yml:75` runs vitest with
   `|| true`, and the workflow runs on push to `main` and on dispatch only, never on a pull
   request (`.github/workflows/vitest.yml:2-5`). [C]
3. **Publishing does not follow green tests.** `.github/workflows/publish.yml` runs on every
   push to `main`, in parallel with CI, runs no tests, and skips a version that is already on
   npm (`.github/workflows/publish.yml:59-60`). The fix that keeps a session usable after a
   failed save (commit `71f37d7`) landed after `0.1.0-canary.8` was published (2026-10-01)
   without a version bump, so it is not shipped. [C, npm `dist-tags`]
4. **Range dependencies are scanned linearly.** `DepGraph::dependents_of` walks every
   registered range key for every written cell (`sheet-calc/src/graph.rs:236-250`), and
   `precedents_in` tests every dirty candidate against every range key of a cell
   (`sheet-calc/src/graph.rs:256-281`). A running-total column (`=SUM($A$1:A1)` filled down)
   registers one range per row, so one edit at the top costs about N² containment tests. The
   module header names this the interval-index seam (`sheet-calc/src/graph.rs:41-47`). [C for
   the code; the N² is read from it, not measured]
5. **Every range argument is copied cell by cell.** `materialize_range` allocates and fills
   rows × cols values, blanks included, on each evaluation
   (`sheet-calc/src/argview.rs:100-125`). The module header
   (`sheet-calc/src/argview.rs:49-52`) and the function comment
   (`sheet-calc/src/argview.rs:96-99`) say the view is capped at the populated bounding box
   and only populated cells are read; no such cap exists. The formula tree is cloned per
   evaluation (`sheet-calc/src/lib.rs:516`, `sheet-calc/src/lib.rs:654`). [C]
6. **Dependents of volatile cells are never recalculated.** `recalc_dirty` reseeds only the
   volatile cells themselves (`sheet-calc/src/lib.rs:396`, `sheet-calc/src/dirty.rs:121-125`);
   unlike `propagate_from` (`sheet-calc/src/dirty.rs:94-107`) it does not dirty their
   dependents, so `=A1*2` over `A1 = RAND()` keeps its old value after a recalc. [C, by
   reading; a failing test pins it before the fix]
7. **Placing a range is one host round trip per cell.** `pourCellContent` sends one awaited
   `document.mutate` per non-empty cell (`packages/sheet-bundle/src/lower.ts:201-205`). Its
   comment (`packages/sheet-bundle/src/lower.ts:182-191`) says text cannot ride a batch. That
   was true until the engine taught `Mutation::Batch` to carry text edits as one undo entry
   (core `v0.61.0`) and to rebuild once per batch (core `v0.63.0`); the editor ships
   `0.64.0`. The gap is now plugin-only. [C]
8. **Built, not reachable.** Styled page lowering (the page calls the unstyled door,
   `packages/sheet-bundle/src/lower.ts:312`; `getRangeStyled` serves only the Character
   panel, `packages/sheet-bundle/src/activate.ts:383`), conditional formatting on the page,
   pagination across threaded frames (`lowerPaginatedToChain` at
   `packages/sheet-bundle/src/lower.ts:626` and `subscribeChainReflow` at
   `packages/sheet-bundle/src/lower.ts:692` are exported; no command or panel calls them),
   insert and delete rows or columns (`Engine::apply_edit` at `sheet-calc/src/lib.rs:475`, no
   `sheet-js` door), iterative calculation (the engine iterates; no reader sets
   `calc.iterative`: grep of `calcPr` and `iterative` in `sheet-xlsx/`, 0 hits), and the clock
   (`set_now` is exported at `sheet-js/src/lib.rs:426`; grep of `setNow` and `set_now` in
   `packages/`, 0 hits, so `NOW` and `TODAY` evaluate at serial 0). [C]
9. **The in-frame grid invalidates every page cache per change.** Each grid change submits a
   fresh scene layer (`packages/sheet-bundle/src/session.ts:638`), and the engine answers
   `SubmitSceneLayer` with a whole-cache invalidation (core
   `crates/paged-canvas-wasm/src/dispatch.rs`, lines 784–808: `CacheEffect::ClearAll`). This
   one needs the engine. [C]

## 5. Calculation: what Excel is compared with

- Every expected value in `sheet-conformance` is hand-written. [S]
- The LibreOffice differential tests are `#[ignore]` and end in `todo!()`
  (`sheet-conformance/tests/oracle.rs:76-85`, `sheet-conformance/tests/oracle.rs:96-104`). [C]
- The coverage gate accepts a test pointer when the named file contains the text
  `fn <name>` (`sheet-conformance/src/bin/coverage_gate.rs:242`); an ignored or `todo!()`
  test passes it. [C]
- A corpus of 414 workbooks kept outside this repository (17 authored in Excel, 397
  converted by Excel) carries Excel's own cached values. The real-workbook test
  (`sheet-conformance/tests/real_xlsx_corpus.rs`) is opt-in, never runs in CI, and asserts
  that files open or are refused, not that values match. [C for the test; S for the counts]
- No XLSX round-trip property test and no fuzz target. [S]

The plan replaces the LibreOffice stub with Excel itself: workbooks generated from the
function corpus, recalculated and saved by Excel, their cached values recorded as fixtures
and replayed in CI without Excel; plus the corpus workbooks' cached values as a
recalculation oracle.

## 8. Records that disagree with the code

Corrected on 2026-10-04 unless marked otherwise.

- **The repository orientation file** said pagination across the frame chain is live, the
  owned-content interception and the range clipboard are open, and per-cell fill and borders
  await a `tableCell` element kind. Pagination has no command; interception and the
  clipboard shipped in June 2026; per-cell fills, borders and `appliedCellStyle` apply on a
  `tableCell` today. Corrected.
- **Panel and session text** said applying a cell style is pending the platform
  (`packages/sheet-bundle/src/panels/workbook-panel.tsx:587`,
  `packages/sheet-bundle/src/session.ts:328-331`,
  `packages/sheet-bundle/src/session.ts:1518-1534`). The engine applies `appliedCellStyle` on
  a table cell. Corrected to report the outcome without blaming the platform.
- **The `registry/functions/array.yaml` header** said all rows are planned; all eight are
  implemented. Corrected.
- **Feature registry rows** (claims edited, not prose): pagination was claimed shipped and
  live (no command reaches it); page lowering claimed a style map on the page (the page uses
  the unstyled door) and per-cell fill as open (it works); conditional formatting claimed
  lowering to style overrides on the page (data bars draw in the grid only); iterative
  calculation claimed a `calcPr` round trip (not read); the bundle row claimed 7 commands and
  68 tests (12 commands).
- **Survey claims corrected here:** the panels are 3, not 2; `materialize_range` sits at
  `sheet-calc/src/argview.rs:100-125`; the batched table pour is no longer an engine gap
  (headline 7).
- **`packages/sheet-bundle/src/lower.ts:182-191`** still says text cannot ride a batch. Left
  until the pour is rewritten.

Engine gap to file in the platform gap register: per-frame invalidation for a vector scene
layer (headline 9). The batched pour needs no row.

## 10. Changed since the analysis

On the development branch, not yet published unless stated:

- Edits persist: every committed engine write re-saves the workbook after a short quiet
  period through the existing save path, to both the container part and the blob, and
  deactivation flushes (headline 1).
- The vitest workflow fails on a red spec and runs on pull requests; publishing runs only
  after green CI, runs the tests, and refuses a source change without a version bump
  (headlines 2 and 3).
- The wasm carries a source-hash stamp and a spec fails on a stale build.
- Both packages pin plugin-api and plugin-sdk `0.2.37-canary.0`; a spec checks the pin.
- The coverage gate counts only runnable tests: an `#[ignore]` or `todo!()` test no longer
  satisfies a row.
- The package version is `0.1.0-canary.9`, which carries these changes and the save fix of
  headline 3 once it is published.
- The stale records in §8 are corrected.
